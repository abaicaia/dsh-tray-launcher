## 二、改造决策（与老板确认过的方向细化）

### D1. 拆文件方案：单文件 → 4 文件（同项目，csc 多文件编译）
```
启动器\
├── DshLauncher.cs      → 保留：Main 入口 + 命令分发表 + 托盘 UI 装配
├── LauncherConfig.cs   → 新：路径族 + conf 读写 + 端口/URL（原 64-176）
├── LauncherLog.cs      → 新：日志/轮转/ReadTail（原 178-231）
├── LauncherCore.cs     → 新：探测 + 进程治理 + 启停 + 打开 UI（原 233-561）
├── ModeGate.cs         → 新：状态机（v1.1 先支持 Normal/Stopped，Rescue 占位）
├── build.cmd           → 改：csc *.cs 通配编译
└── （AssemblyInfo.cs 保留）
```
理由：csc 一次编 4-5 个文件毫无压力；文件按职责分，单文件最长 ~300 行，可读性大增。

### D2. 状态机（ModeGate，本版最小实现）
```csharp
public enum LauncherMode { Normal, Rescue, Stopped }
public static class ModeGate {
    static string ModeFile => Path.Combine(DataDir, "launcher-mode");
    public static LauncherMode Current { get; }   // 启动读一次，内存态
    public static bool IsRescue => Current == LauncherMode.Rescue;
    // v1.1 只有读 + Normal/Stopped 推断；Rescue 枚举占位，Enter/Exit 留 v1.2
}
```
- 现在 mode 文件不存在 = Normal（向后兼容：行为与 v1.0.0 完全一致）
- ModeGate 是**纯新增**，不改变任何现有行为，但所有命令入口将来只需在 ModeGate 挂检查

### D3. 命令分发（Main 重构）
- 保留 Mutex/异常钩子/参数解析结构，把 **if/else 链抽成静态分发表**：
```csharp
static Dictionary<string, Action<Options>> Commands = new() {
    ["--help"] = o => WriteHelp(),
    ["--status"] = o => WriteStatusFile(),
    ["--selftest"] = o => WriteSelfTestFile(),
    ["--stop"] = o => OneShotStop(),
    ["--start"] = o => OneShotBoot(o.NoOpen),
    ["--restart"] = o => OneShotBoot(o.NoOpen),
    // v1.2: ["--rescue"] = o => RescueCoordinator.Enter(),
    // v1.2: ["--exit-rescue"] = o => RescueCoordinator.Exit(),
};
```
- 加新命令 = 注册一行 + 写一个方法，**不碰任何旧代码**

### D4. 托盘菜单解耦（关键防屎山动作）
- 现状：菜单回调内联 `EnsureRunningAndOpenUi()` 等（741-760 行）
- 改后：菜单只调 `Coordinator.Xxx()`（方法已存在，只是搬位置/改名清晰化），**行为不变**；以后救援菜单项 = 加一项 + ModeGate 控制灰显

### D5. 明确不做（防过度设计）
- 不做通用插件框架、不做 IoC/DI、不加无调用方的抽象接口
- RescueCoordinator 类 v1.1 **不创建**（留待 v1.2 真正实现时按需建）
- 不顺手修 bug（本次只搬不修，行为零变化是验收标准）

## 四、验收标准（v1.1 的"完成"定义）

1. **行为零变化**：所有 v1.0.0 功能（托盘菜单 6 项、命令 7 个、日志格式、自启、3199 冷启动）逐一实测一致
2. **编译干净**：csc 零警告零错误
3. **新代码可扩展**：命令表加一行 = 新命令可用（用 --help 验证表驱动生效）
4. **运行内存不增**：托盘 ~47MB 上下（重构不引入新依赖）
5. 老板验收通过后才 commit v1.1.0

## 五、风险与回滚

- **风险**：搬移过程手误改逻辑 → 靠 S5/S6 双验证兜底；git 快照可随时回滚
- **回滚**：v1.0.0 commit 后，任何一步出问题 → `git checkout` 还原 + 重编
- **注意**：重构期间运行中的托盘是旧 exe，编译新 exe 前需停旧托盘（8/17 教训：CS0016 文件占用）；DSH 3080 服务可不动（exe 与 node 进程独立）
