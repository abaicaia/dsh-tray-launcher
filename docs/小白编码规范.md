# 小白编码与编译规范（Windows / DSH 环境专用）

> 写给你（小白/OpenClaw）在 **Windows + DSH 环境**写脚本/程序前必读。
> 规则全部来自本机实测踩坑（小D AGENTS.md 教训库 + 你 2026-09-03 事故报告）。
> 原则：**文件编码错 = 静默乱码或语法爆炸；编译编码错 = 中文全乱**。动手前 10 秒对表。

---

## 一、文件编码三件套查表（最重要的表）

| 目标文件类型 | 行尾 | BOM | 字符集 | 中文怎么写 |
|---|---|---|---|---|
| `.cmd` / `.bat`（cmd.exe） | **CRLF** | 无 | **纯 ASCII** | ❌ **禁止中文**（GBK 代码页解码必乱）。中文一律放 .ps1 |
| `.ps1`（PowerShell 5.1） | 任意 | **必须 UTF-8 BOM** | UTF-8 | ✅ 可写中文，但**文件必须有 BOM**，否则 5.1 按 GBK 读 → 中文注释把解析搞炸（`Unexpected token`） |
| `.ps1`（pwsh 7+） | 任意 | 可无可有 | UTF-8 | ✅（统一按 5.1 标准加 BOM 最稳） |
| `.py` | 任意 | **无 BOM** | UTF-8 | ✅ 可写；**打印中文前**设 `$env:PYTHONIOENCODING="utf-8"`，否则 GBK 控制台 `UnicodeEncodeError` |
| `.cs`（csc 编译） | 任意 | **必须 UTF-8 BOM** | UTF-8 | ✅ 可写中文注释/字符串，但编译时文件必须带 BOM（见 §二） |
| `.js` / `.mjs` | 任意 | 无 BOM | UTF-8 | ✅ 可写；**模板字符串里路径反斜杠会被剥**（`\Users` → `Users`）→ 用单引号或双反斜杠 |
| 给程序读的 `.json` | 任意 | **必须无 BOM** | UTF-8 | ✅ 可写；BOM 会让 `JSON.parse` 报 `Unexpected token '﻿'` |

**血的教训**：edit/write 工具写 .ps1 默认 **无 BOM UTF-8** → PowerShell 5.1 按 GBK 读你的中文注释 → 中文字节被拆坏 → 报一堆莫名其妙的 `Unexpected token ')'`。你 2026-09-03 的 test-fallback-B.ps1 用"全 ASCII + `[char]0x8F6C` 拼中文"绕开了，这是**有效但笨**的办法——正确做法是：写完后给 .ps1 加 BOM（见 §五），就能直接写中文了。

## 二、C# / csc 编译规则（.NET Framework 4.0 老编译器）

1. **源文件必须 UTF-8 BOM**：csc 无 BOM 时按 ANSI/GBK 解码源码 → 中文注释/字符串全乱（编译能过但 UI 全乱码）。症状：编译无错但运行显示「鍚姩」类乱码。
2. **禁止 C# 6+ 语法**：本机 csc 是 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（.NET 4.0）！
   - ❌ 字典索引初始化器：`new Dictionary<K,V> { ["a"] = x }` → **CS1003/CS1525 语法错**
   - ❌ 字符串插值：`$"port={p}"` → 同样报错
   - ❌ `?.` / `??` / `using var` / `nameof` / 表达式体成员 / `=>` 属性
   - ✅ 用 `d.Add("a", x)`、`string.Format` 或 `+` 拼接、老式 `delegate(...){}`
3. **引用的程序集要显式加**：`/r:System.Windows.Forms.dll /r:System.Drawing.dll /r:System.Management.dll /r:System.Core.dll`（build 脚本已配好，别自己精简）。
4. **多个 .cs 一起编译**：`csc ... a.cs b.cs c.cs`（同项目多文件，别把每个文件单独编）。
5. **字符串里的中文**：源码带 BOM 就没问题；**Windows 路径字面量**注意 C# 里 `"C:\\Users\\..."` 双反斜杠（C# 无 JS 模板字符串剥路径问题，但转义仍要正确）。

## 三、PowerShell 5.1 运行环境（本机 DSH 工具/脚本的默认环境）

1. **执行策略挡 .ps1**：`running scripts is disabled` → 用
   `powershell.exe -NoProfile -ExecutionPolicy Bypass -File script.ps1`
   （DSH 终端里跑脚本：先 `Set-ExecutionPolicy -Scope Process Bypass -Force` 再 `& script.ps1`）
2. **`pwsh` 不在 PATH**：嵌套调用会报「pwsh 不是内部命令」。统一用 `powershell.exe` 或直接跑。
3. **函数输出流 = 返回值流**：函数内 `Write-Output` 会被 `$r = fn` 吞掉 → 要"打印"用 `Write-Host`，函数只 return 数据对象。
4. **函数返回数组**：`return ,$arr`（逗号包裹，防管道拆散）。
5. **中文路径字面量**：pwsh 命令行里写字面中文路径可能被 GBK 解码错 → 用 `Get-ChildItem | Where-Object Name -match '中文'` 拿真实 FullName，或 `[char]0xXXXX` 拼。
6. **读 UTF-8 文件**：`Get-Content` 按本地代码页读会乱 → 用 `[IO.File]::ReadAllText($p)`（默认 UTF-8）或 `Get-Content -Encoding UTF8`。
7. **写 UTF-8 无 BOM 文件**：`[IO.File]::WriteAllText($p, $t, New-Object Text.UTF8Encoding($false))`；`Set-Content -Encoding UTF8` 在 5.1 会写 **BOM**（给 JSON 写配置会炸）。

## 四、bash/cmd 方言陷阱（DSH pwsh 工具 ≠ cmd）

1. **.cmd 行尾必须 CRLF**，括号块内禁止 `( ) & | < >` 字符。
2. **DSH pwsh 工具里跑 node/python**：会 spawn EPERM（命名管道限制）→ 用安装版 CLI 的 bin 入口，别裸 spawn。
3. **git + github.com**：主站连不上是网络黑洞（非配置问题）→ 用 `api.github.com` / `raw.githubusercontent.com` / `codeload.github.com` 绕。
4. **调外部 exe 后判断成败**：不信管道合并退出码（截断误报），单独跑看 `$LASTEXITCODE`；失败看 stderr。

## 五、写完必做的三道验证（不验不算完）

1. **编码验证**：跑小D的检查工具（若可用）或自查：
   - .ps1 前 3 字节 = `239 187 191`（EF BB BF = BOM）
   - .json 前 3 字节 ≠ `239 187 191`（无 BOM）
   - .py/.cs 能正常读回中文（用 read 工具/编辑器看，不是 Get-Content）
2. **语法验证**：PS 脚本用 `[System.Management.Automation.Language.Parser]::ParseFile($p, [ref]$null, [ref]$errs)` 检查；C# 直接编译看报错。
3. **实测最小样例**：别一次跑大逻辑，先最小复现。报错看**文件编码状态**再查逻辑。

### .ps1 加 BOM 的一条命令
```powershell
$t = [IO.File]::ReadAllText('x.ps1', New-Object Text.UTF8Encoding($false))
[IO.File]::WriteAllText('x.ps1', $t, New-Object Text.UTF8Encoding($true))
```

## 六、快速症状对照

| 症状 | 大概率原因 | 解法 |
|---|---|---|
| `. was unexpected at this time.` / exit 255 | .cmd 是 LF 行尾 或 括号内特殊字符 | 转 CRLF |
| 中文乱码：锟斤拷 / 鍚姩 / 宸ヤ綔 | 文件编码与读取方不匹配（BOM 缺失 / GBK-UTF8 混） | 查三件套表 |
| `Unexpected token '﻿'` | JSON 带 BOM | 去 BOM |
| `Unexpected token ')'` 在 .ps1 里 | **中文注释无 BOM，5.1 按 GBK 读炸了** | 加 BOM |
| csc 编译 CS1003/CS1525 | 用了 C# 6+ 语法（索引初始化器/插值） | 改老语法 |
| 编译过但运行中文乱 | .cs 无 BOM | 加 BOM 重编 |
| python 打印中文 UnicodeEncodeError | stdout 走 GBK | `$env:PYTHONIOENCODING="utf-8"` |
| 路径变 `C:Userswan` | JS 模板字符串 `\U` 被剥 | 单引号 / 双反斜杠 |
| 脚本/命令"卡住不退出" | **MessageBox/模态弹窗在无人值守** | 命令行工具不弹 GUI 窗，写日志 |
| 管道连上但命令没执行 | 连上僵尸句柄 / 无 ACK 确认 | 协议要 ACK（本机启动器已修） |
